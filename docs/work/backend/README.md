# 백엔드 · 익명 탑승 결과 기록

담당: **유민준** · 작업 브랜치: **`be/boarding-record`**

목표는 사용자가 조회 후 실제 탑승 결과를 남길 수 있도록 기록 기능을 설계하고 구현하는 것입니다. **현재 구현된 기능이 아니라 이번 작업의 목표**입니다.

## 1. 작업 브랜치로 이동

저장소 최상위에서 처음 한 번 실행합니다. 이미 로컬 브랜치가 있다면 `git switch be/boarding-record`로 이동합니다.

```sh
git fetch origin
git switch --track origin/be/boarding-record
```

## 2. 기존 서버 실행

[공통 협업 안내](../../../CONTRIBUTING.md)의 Python 3.11 설치·실행 방법을 따릅니다. 기본 샘플 모드는 API 키 없이 화면과 예측 연결을 확인할 수 있습니다.

기존 상태 확인과 예측 요청이 정상인지 먼저 확인합니다. 주요 수정 위치는 `hanjari-web/backend/`입니다.

## 3. 기록 방식 합의

1. 어떤 조회의 결과인지 연결하는 방법을 프론트엔드·AI 담당자와 정합니다.
2. 기록 항목, 저장 위치, 보관 기간과 참여 동의 방식을 정합니다.
3. 관측하지 못한 결과와 실제 탑승 실패를 구분합니다.
4. 이름·연락처 등 필요 없는 개인정보는 받지 않습니다.

현재 프로젝트에 이미 기록용 데이터베이스나 테이블이 있다고 가정하지 않습니다. 먼저 저장 방식을 정하고 문서에 남깁니다.

## 4. 구현과 확인

- 정상 기록, 잘못된 입력, 중복 제출과 저장 실패를 확인합니다.
- 기존 예측 API의 입력 범위 0~40명과 응답 형식을 유지합니다.
- 기존 화면에서 조회가 계속 동작하는지 확인합니다.
- 자동 테스트에는 가상의 자료와 임시 저장 위치를 사용합니다.

운영 자료를 테스트에 직접 사용하지 않으며, 저장 기술을 추가하면 설치 목록과 실행 안내도 함께 수정합니다.

## 5. PR 작성

[공통 협업 안내](../../../CONTRIBUTING.md)에 따라 업로드합니다. PR에 기록 항목, 요청·응답 예시, 확인 결과를 적고 황정원과 최지용에게 검토를 요청합니다. 화면 연동이 필요한 부분은 서재현에게 공유합니다.

운영 서버에 데이터베이스를 설치하거나 서비스를 재시작하지 않습니다.
