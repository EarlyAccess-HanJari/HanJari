# 프론트엔드 · 화면 사용성 개선

담당: **서재현**

2개 화면(탭·스와이프) UI는 `main`과 운영 서버(v9)에 반영되어 있습니다. 앞으로의 작업은 표시 오류를 고치고, 현장 관측과 사용성 평가에서 나온 불편을 개선하는 것입니다.

## 현재 구현

- 첫 화면: 이번·다음 버스 도착 시간, 지금 인원(서울시·태그 기준), 도착 때 인원(한자리 예측), 탈 수 있는지, 대기 인원 입력, 같은 노선 다른 정류장(도착 시간만)
- 둘째 화면: 앞·뒤 정류장 타임라인
- 입력: `+`/`-`와 빠른 선택(5, 10, 15, 20, 25, 30명), 직접 입력(0~40명). 기본값이 없고, 입력 전에는 탈 수 있는지 말하지 않으며 신호등 색도 쓰지 않습니다.
- 색은 서버 판정(`level`)을 따릅니다. 확률이 높아도 서버가 `빠듯함`이면 주황입니다.
- 인원은 숫자 하나로 말하고, 범위가 3명 이내면 말끝을 "일 거예요"로 바꿉니다(`isSettled`, 임시 기준).
- 차량번호는 화면 설계 방침에 따라 표시하지 않습니다.

## 남은 작업

| 기한 | 작업 | WBS |
| --- | --- | --- |
| 11/14 | 표시 오류 수정, 현장 불편 개선 | 5.3 |
| 11/26 | 사용성 평가 피드백과 오류 반영 | 5.10 |
| 11/30 | 최종 회귀·통합시험 | 6.1 |

### 먼저 고칠 문제

- 360×640 화면에서 다른 정류장 목록이 잘려 스크롤이 필요하고, 오류 제목 줄바꿈이 어색합니다.

오류·지연 화면의 문제는 [오류·지연 안내 개선](../frontend-status/README.md)에 정리했습니다.

### 결정이 필요한 것

v6에 있던 "앱 설치" 버튼, 로고, ARS 번호, "등교 방향" 문구가 v7에서 빠졌습니다. 유지 여부를 황정원과 정한 뒤 반영합니다.

버스가 몇 명까지 타는지는 지금 보여 주지 않습니다. 응답에 새 항목이 필요하고 정원 값이 현장에서 검증되지 않았습니다. 11/9~11/13 기록으로 실제 정원을 확인한 뒤 정합니다.

## 실행

Node.js 24 기준입니다. `.env`가 없다면 `.env.example`을 복사합니다. `VITE_MOCK=1`이면 저장된 예시 자료로 화면을 확인할 수 있습니다.

```sh
cd hanjari-web/frontend
npm ci
npm run dev
```

## 테스트와 빌드

```sh
npx playwright install chromium
npm test
npm run build:prod
```

`api-quality`, `status-api` 테스트는 실제 API 연결 모드(`VITE_MOCK=0`)에서 확인합니다. 이 저장소는 `dist/`도 관리하므로 화면 수정 후 빌드 결과를 소스와 함께 검토합니다. 테스트 보고서와 `node_modules/`는 올리지 않습니다.

입력·표시 경계 시험은 완료했습니다. 2026-11-06 기준 목업 모드 202개 통과(실제 API 경로 전용 40개는 건너뜀), `VITE_MOCK=0` 44개 통과입니다. 전에 간헐 실패가 있던 `도착 시간이 1초씩 줄어든다`는 6.1 최종 회귀·통합시험에서 다시 확인합니다. 아이폰은 11/9~11/13 전원 등교 기록 때 확인합니다.

## PR

[공통 협업 안내](../../../CONTRIBUTING.md)에 따라 최신 `main`에서 브랜치를 만듭니다. PR에 변경 전후 화면과 테스트 결과를 적습니다. API 응답 항목과 예측 단계의 의미는 임의로 바꾸지 않습니다. 운영 배포는 유민준과 합의합니다.
