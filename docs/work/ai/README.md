# AI · 예측 모델 검증

담당: **최지용**

목표는 API 기준 평가와 실제 탑승 평가를 구분해, 모델이 실제로 얼마나 맞는지 확인하는 것입니다. 수집과 매일 자동 재학습은 운영 중입니다.

## 현재 상태

- 모델: XGBoost 라이트 모델. 2026-11-05 재학습 기준 학습일 31일(2026-09-23~11-04)입니다.
- API 재생 평가(11/4 자료): 오차 2.58명, 현재 승객 수를 그대로 쓰는 기준 4.34명입니다.
- 이 수치의 정답도 API 인원입니다. **실제 탑승 성능이 아니며**, 현장 평가는 아직 없습니다.
- 수집 자료에 방학 기간은 없고, 시험 기간은 2026년 2학기 중간고사 한 번입니다.

## 남은 작업

| 기한 | 작업 | WBS |

| 11/8 | 관측 전 모델 복사·보관, 11/9~11/13 기간 모델 버전 보관 | 4.20 |

자동 재학습은 계속하며 서비스 모델을 고정하지 않습니다. 최지용이 11/8 관측 전 모델과 11/9~11/13 관측 기간 모델 버전을 복사해 보관합니다. 최근 7개 버전만 남기는 정리에서 보관본이 삭제되지 않게 하고, 기록표 시각과 `models.csv`로 예측 모델을 찾습니다. 보관 작업은 아직 미실시입니다.

전원이 각자 등교 때 앱을 쓰고 공유한 Google 스프레드시트에 기록합니다. 시간표와 영상 촬영은 쓰지 않습니다. 현장 합격 기준(표본 수·달성 판단 기준)은 4.10에서 확정합니다.

### 피드백 반영 (담당과 기한 협의 중)

- 공공 API 현재값과 모델 예측의 차이를 정확히 설명합니다. 비교 기준이 무엇인지 함께 밝힙니다.
- 학습 구조를 쉽게 설명하고, 평소·수업 직전·시험 기간·요일별 성적을 나눠 제시합니다.
- 학사 일정 영향은 승차 인원 변화율(%)로 제시합니다. 학교 행사는 같은 요일의 전주·후주와 비교하고, 학교와 무관한 인근 정류장을 대조군으로 쓰며, 여러 학기의 같은 행사를 모아 봅니다.
- 갑작스러운 승객 증가처럼 예측하기 어려운 상황의 한계를 사례와 수치로 정리합니다.

## 현재 결과 확인

[공통 협업 안내](../../../CONTRIBUTING.md)에 따라 Python 환경을 준비합니다. Windows에서는 저장소 최상위에서 아래 명령으로 포함된 샘플을 예측합니다.

```powershell
.\.venv\Scripts\python.exe hanjari-ml/src/serve.py sample 3
```

이 명령은 저장된 자료를 사용하며 외부 버스 API를 호출하지 않습니다. 과거 수집 로그와 전체 학습 자료는 저장소에 없습니다.

## 비교 규칙

- 학습 날짜와 평가 날짜를 나누고, 평가 자료가 학습에 들어가지 않게 합니다.
- 같은 평가 자료에서 기준 모델과 새 모델의 MAE·Brier를 비교합니다.
- 자료 기간, 평가 건수, 모델 생성일과 변경 내용을 함께 기록합니다.
- API로 만든 학습 정답과 사람이 확인한 실제 탑승 결과를 구분합니다.
- 사용자 직접 제출값은 수집하지 않습니다.

자료가 부족하면 성능 개선을 단정하지 않습니다. 수집기를 고치면 `hanjari/src/collect.py`와 `hanjari-ml/src/collect.py`가 어긋나지 않도록 합니다. 대용량 학습 자료와 수집 로그는 Git에 올리지 않습니다.
