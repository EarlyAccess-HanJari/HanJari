# AI · 예측 모델 개선

담당: **최지용** · 작업 브랜치: **`ai/prediction-improvement`**

목표는 현재 모델을 기준으로 입력 자료와 예측 결과를 점검하고, 같은 조건에서 개선 효과를 확인하는 것입니다.

## 1. 작업 브랜치로 이동

저장소 최상위에서 처음 한 번 실행합니다. 이미 로컬 브랜치가 있다면 `git switch ai/prediction-improvement`로 이동합니다.

```sh
git fetch origin
git switch --track origin/ai/prediction-improvement
```

## 2. 현재 결과 확인

[공통 협업 안내](../../../CONTRIBUTING.md)에 따라 Python 환경을 준비합니다. Windows에서는 저장소 최상위에서 아래 명령으로 포함된 샘플을 예측합니다.

```powershell
.\.venv\Scripts\python.exe hanjari-ml/src/serve.py sample 3
```

이 명령은 저장된 자료를 사용하며 외부 버스 API를 호출하지 않습니다. 현재 모델과 샘플은 포함되어 있지만, 과거 수집 로그와 전체 학습 자료는 별도로 준비해야 합니다.

## 3. 개선할 부분 선택

1. 현재 승객 수가 없거나 정보가 오래된 경우의 처리를 점검합니다.
2. 시간대·정류장별 오차와 확률 보류 결과를 확인합니다.
3. 한 번에 한 가지 변경을 적용하고 기존 모델과 비교합니다.

주요 수정 위치는 `hanjari-ml/src/`와 필요한 모델 파일입니다. 수집기를 고치면 `hanjari/src/collect.py`와 `hanjari-ml/src/collect.py`의 관계도 확인해 두 사본이 어긋나지 않도록 합니다.

## 4. 같은 조건으로 비교

- 학습 날짜와 평가 날짜를 나누고, 평가 자료가 학습에 들어가지 않게 합니다.
- 같은 평가 자료에서 기존 모델과 새 모델의 MAE·Brier를 비교합니다.
- 자료 기간, 평가 건수, 모델 생성일과 변경 내용을 함께 기록합니다.
- API로 만든 학습 정답과 사람이 확인한 실제 탑승 결과를 구분합니다.

자료가 부족하면 성능 개선을 단정하지 않고 샘플 점검 결과만 남깁니다. 새 모델을 반영할 때는 예측 코드·설정·결과 형식의 호환성을 확인합니다. 대용량 학습 자료와 수집 로그는 Git에 올리지 않습니다.

## 5. 연결 확인과 PR

샘플 서버를 실행해 기존 화면이 예측 결과를 표시하는지 확인합니다. [공통 협업 안내](../../../CONTRIBUTING.md)에 따라 PR을 만들고, 비교 조건과 결과를 적어 유민준에게 연결 검토를 요청합니다.

운영 서버의 자동 학습·모델 교체·배포 작업은 실행하지 않습니다. 포함된 운영 설치 스크립트도 이번 로컬 점검에 사용하지 않습니다.
