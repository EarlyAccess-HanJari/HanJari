-  프로젝트 개요

- **우리 서비스는 한성대입구역의 한성대 방향 지정 정류장에서 첫 번째 성북 02번 버스의 탑승 가능성을 추정하는 반응형 웹 서비스이다.**

- **사용자는 버스 도착시간을 알아도 차량 혼잡도와 자신의 대기 순서 때문에 첫 번째 버스에 탈 수 있는지 판단하기 어려운 문제를 겪고 있다.**

- **이 문제가 발생하는 이유는 도착 예정시간만으로는 차량의 수용 여유와 내 앞 대기 인원을 함께 고려하기 어렵기 때문이다****.**

- **따라서 우리는 조회 시점의 내 앞 대기 인원과 확보 가능한 실시간 정보를 활용하여 첫 번째 버스의 탑승 실패 가능성을 미리 판단하기 어려운 문제를 해결하고자 한다.**

- **사용자가 우리 서비스를 이용하면 첫째·둘째 버스의 도착정보와 검증된 범위의 탑승 가능성을 참고하여 대기를 계속할지 다른 이동 방법을 고려할지 판단할 수 있다.**

- 핵심 기능(MVP) 

우리 팀의 MVP는 버스 도착정보와 앞 대기 인원을 바탕으로 첫 번째 버스의 탑승 가능성을 알려주는 웹 서비스이다.

| **ID** | **핵심기능** | **설명** | **우선순위** |
| --- | --- | --- | --- |
| F-01 | 버스 정보 조회 | 첫째·둘째 버스 도착시간과 첫째 버스의 위치 또는 남은 정류장 수를 보여준다. | 필수 |
| F-02 | 앞 대기 인원 입력 | 자기 앞의 대기 인원을 입력한다. 상황이 바뀌면 값을 수정해 다시 조회한다. | 필수 |
| F-03 | 탑승 가능성 예측 | 시간·요일·대기 인원·도착정보와 제공되는 혼잡도 정보를 활용해 첫 버스의 탑승 가능성을 예측한다. | 필수 |
| F-04 | 예측 표시 조건 | 지원 범위 밖이거나 정보가 부족·오래된 경우, 성능 검증을 통과하지 못한 경우에는 확률을 표시하지 않는다. | 필수 |
| F-05 | 상태·오류 안내 | 갱신 시각, 정보 없음, API 장애, 운행 종료를 구분해 안내한다. | 필수 |
| F-06 | 평가 데이터 기록 | 입력값과 실제 탑승 결과를 익명으로 기록하고, 날짜별로 학습·평가 자료를 나눈다. | 필수 |
| F-07 | 모델·사용자 평가 | 기준 모델과 예측 성능을 비교하고, 학생 대상 테스트로 판단 도움과 입력 부담을 확인한다. | 필수 |

- 사용자 흐름(User Flow) - 도식화로 표현

- **기본 흐름**

- 1. 한자리 접속 →

- 2. 버스 도착정보 확인 → 앞 대기 인원 입력 →

- 3. 입력값·정보 확인

- ├ 이용 가능 → 탑승 가능성 확인 → 대기 여부 판단

- └ 이용 불가 → 이유 안내·도착정보만 표시

- 4. 상황이 바뀌면 인원 수정 → 다시 조회

- **주요 예외**

- 잘못된 입력 → 수정 안내
정보 부족·오래된 정보·지원 범위 밖 → 예측 보류
API 장애·운행 종료 → 상태 안내
대상 버스 변경 → 이전 예측을 지우고 재조회
