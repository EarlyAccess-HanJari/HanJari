# 2026-11-02 API 인원 불일치와 정원 계산 수정

실제 탑승 시 센 인원은 21명인데 서비스의 API 원본은 50명 이상이었다는 제보가 있었습니다. 제보의 차량·시각과 실인원을 여기서 독립 확인한 것은 아닙니다. 코드에는 `max(잠정 정원, 학습 API 인원 최댓값)`을 정원으로 쓰는 구조가 있었고, API 과대값이 판단 정원까지 높일 수 있었습니다.

## 변경

- 관측 최대 정원을 학습·평가·서빙에서 제거했습니다. 기존 모델에 남은 `cap_obs`도 읽어 적용하지 않습니다. 성북02 유형 0은 33명, 그 외 기존 유형은 55명으로 고정합니다. **확인된 차량별 법정 정원이 아니라 기존 잠정값입니다.**
- 점 예측과 분위수를 잠정 정원에서 자르지 않습니다. 실제 정원이 미확인인 상태에서 API 예측값을 잘라 범위를 좁히거나 확률을 높이지 않습니다. 0 이상 제한만 유지합니다.
- 새로 검증한 정원표와 후처리 버전을 모델의 `capacity_policy`에 기록합니다. 기존 모델, 정책 불일치 모델, 잠정 정원을 넘는 현재 API 인원은 기존 `확률 보류`/`reason` 응답으로 처리합니다.
- 확률 보류 화면에서는 현재·예상 인원 숫자도 숨깁니다. 원본 `r_now`와 계산 `p_board`는 응답에 보존해 조사할 수 있으며, 소비자는 `level`을 먼저 확인해야 합니다. 도착 정보와 입력 범위 0~40명은 유지합니다.
- 문서와 일일 보고 생성 코드의 '실제 탑승률' 표현을 API 기준 계산 지표로 정정합니다. 기존 날짜별 보고·모델 파일은 과거 기록으로 보존합니다.

## 39일 자료 점검

2026-09-23~11-02 자료 400,949행(반복 조회 포함)을 읽었습니다. 학습의 월~토·공휴일 제외 조건을 만족하는 297,611행에서 다음 후보가 발견됐습니다.

| 노선·유형 | 잠정값 | 입력 초과 행 | 정답 초과 행 | 둘 중 하나 이상 초과 행 |
|---|---:|---:|---:|---:|

| 성북02·0 | 33 | 192 | 1,153 | 1,223 |

입력 또는 정답 초과는 합계 1,741행(약 0.585%)입니다. 이는 **잠정값 초과 후보이며 오류 확정 건수·독립 운행 수가 아닙니다.** 입력·정답 모두에 높은 API 값이 들어갈 수 있음을 확인했습니다. 데이터의 차량번호나 원본 로그는 이 보고에 포함하지 않습니다.

재현 스크립트: `src/audit_capacity.py --dataset /path/dataset.csv --output /path/audit.json`. 상세 집계와 데이터 SHA-256은 [집계 JSON](../reports/capacity_audit_20261102.json)에 있습니다. 실제 인원과의 오차율을 계산할 현장 정답은 없습니다.

## 검증과 운영 영향

- `python -m unittest discover -s hanjari-ml/tests -v`: 10개 통과. 정원 팽창·클리핑·확률 단조성·이전 모델 보류·정원표 변경·의심 입력·지연 상태 검사.
- `python hanjari-ml/src/serve.py check`: 통과. 포함된 모델과 샘플로 예측·동시 요청 점검. 외부 API 호출 없음.
- 변경한 Python 14개 파일 구문 검사 통과. 중단된 수정에 남아 있던 `sweep.py`의 빈 함수와 호출도 제거했습니다.
- 프론트엔드 `npm run build:prod` 통과, 배포 파일 갱신. `VITE_MOCK=1 npx playwright test tests/scenarios.spec.ts --grep 'stale|wide' --workers=2`: 모바일·PC 4개 통과.
- 로컬 FastAPI 샘플 모드: 건강 상태, 6개 정류장의 기존 모델 보류, 기존 숫자 필드 유지, -1·41명 입력 400 응답 확인.
- 실제 빌드 화면과 로컬 샘플 API 연결: 393px·1280px에서 보류 시 현재·예상 인원과 확률을 숨기고 도착 정보를 유지하는 것 확인.

**현재 포함된 모델은 예전 검증 정책이므로 이 코드 적용 시 모든 확률 안내가 보류됩니다.** 운영 배포는 PR 검토와 팀 합의 후 별도로 진행합니다. 이번 변경은 잘못된 확신을 표시하지 않도록 하는 조치이며, API의 50명을 실제 21명으로 보정하거나 원본의 정확성을 복구한 결과는 아닙니다.

확률 안내를 다시 열기 전 차량·시각별 현장 대조와 실제 정원 확인, 데이터 처리 기준 합의가 필요합니다. 이후 새 코드로 날짜 분할 검증과 모델 export를 수행하고 API 기준 성적과 현장 성적을 구분합니다. `capacity_policy`만 수동으로 붙여 검증을 우회하지 않습니다. 정제 근거가 없어 이번에는 의심값을 삭제하거나 모델을 재학습하지 않았습니다.

기존 PR #6의 보류 완화 실험은 이전 관측 최대 정원에 의존하므로 병합을 보류하고 새 기준으로 재평가해야 합니다. 그 PR의 '실제 탑승' 수치는 현장 관측이 아닌 API 기준 계산값입니다.
