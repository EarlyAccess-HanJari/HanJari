# AI/데이터 설계 (2026-11-05 현행화)

초기 설계일은 2026-09-23이며, 현재 범위는 [PRD v1.10·WBS v1.13과 마일스톤 v1.5](../../docs/plan/)를 따릅니다. 과거 의사결정 이력은 [TASKS](../TASKS.md)에 남깁니다.

## 1. 학습 정답과 실제 탑승 평가

공공 API에는 실제 탑승 성공·실패 정답이 없습니다. API에 기록된 도착 시 재차 인원을 자동 학습 정답으로 사용합니다. 이 방법이 실제 탑승 검증을 대체하지는 않습니다. 사용자 직접 제출 익명 탑승 기록은 범위에서 제외하고 팀 직접 현장 관측은 유지합니다.

## 2. 예측 구조

```text
조회 시점 스냅샷 + CSV 평균 승하차 + 학사 달력
    → 규칙 기반 인원 추정 + XGBoost 잔차·분위수 예측
    → 도착 인원 R의 분포
    → P(탑승) = P(R − D ≤ C − N − 1)
```

- N: 사용자 앞 대기 인원, 0~40 정수.
- C: 차량별 API 기반 실용 정원. 등록 차량 14대, 성북02 일반 38·저상 60명, 종로03 일반 52·저상 54명. 법정 정원이나 현장 검증 완료값이 아닙니다. `config/boarding_policy.json`과 [11/4 정책 기록](PRACTICAL_CAPACITY_20261104.md)을 따릅니다.
- D: CSV 시간대별 하차 인원과 운행횟수로 구한 평균.
- 관측 최대값으로 정원을 올리거나 예측 인원을 정원에서 자르지 않습니다. 범위폭 20명 초과도 확률로 안내합니다.

## 3. 모델과 단계

운영 모델은 XGBoost입니다. 현재 재차 인원을 그대로 쓰는 기준 모델 및 다른 모델과 동일 자료로 비교합니다. CSV 평균은 초기 기준 모델과 현재 피처에 사용합니다. 평가는 날짜 단위로 분리해 MAE와 확률 지표를 확인합니다.

수업 없는 날, 오래되거나 부족한 자료, 미등록 차량, 모델·정원 정책 불일치 등은 확률을 보류합니다. 그 외에는 칸별 임계값 이상이면 여유 있음, 0.3 이하이면 어려울 수 있음, 중간이면 빠듯함입니다. 임계값은 모델별 `meta.json`을 따르며 [README](../README.md)에 저장소 사본의 값을 기록했습니다.

운영 조회는 `predict_latest`로 저장 자료를 재사용하며 외부 API를 추가 호출하지 않습니다. 180초보다 오래된 스냅샷은 확률을 보류합니다. 화면은 운행 시간 아님·수집 지연·해당 정류장 정보 없음을 구분합니다. 첫 버스의 탑승 확률과 둘째 버스의 ETA(`eta2_sec`)를 제공하며 둘째 버스의 확률은 제공하지 않습니다.
