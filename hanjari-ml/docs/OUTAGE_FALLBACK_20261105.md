# API 장애 때 대체 안내 — 2026-11-05

공공 API나 수집이 3분 넘게 끊기면 지금은 확률을 숨기고 "정류장 안내판을 확인해 주세요"만 보여준다. 11-03 아침에는 등교 시간 2시간 23분(07:00~09:22) 내내 이 화면이었다. 같은 상황에서도 가진 자료로 추정 안내를 내도록 응답에 `fallback`을 더한다. **기존 필드와 지금 화면 동작은 바뀌지 않는다.**

## 끊김 실태 (09-23~11-04)

| 길이 | 횟수 | 원인 |
|---|---|---|
| 3~10분 | 28번(합계 133분) | 짧은 수집 공백 |
| 10분 넘음 | 2번 | 11-02 저녁 3시간 25분(수집기 호출 장부 버그, 수정됨), 11-03 아침 2시간 23분(공공 API 503, 키 4개 공통) |

## 두 단계

| 끊긴 시간 | 모드 | 내용 |
|---|---|---|
| 10분 이내, 첫 버스 도착 예정 전 | `last_known` | 마지막으로 받은 버스·인원으로 낸 확률과 도착 예정 시각을 그대로 쓴다. 판정 기준은 실시간과 같다(창신역4번출구·녹십자약국 0.95 포함). |
| 10분 넘음 또는 첫 버스가 도착했을 시각 지남 | `typical` | 같은 노선·정류장·요일유형(평일/토)·30분 칸의 과거 도착 중 앞 N명이어도 탈 수 있었던 비율. '여유 있음'은 P ≥ 0.98일 때만. |
| 일요일·공휴일, 모델에 표가 없음 | `null` | 지금처럼 안내판 확인 안내 |

## 정확도 (API 인원 기준, 10-25까지로 만들고 10-26~11-04 수업일 도착 5,822건으로 시험)

- '빠듯함'으로 내려간 버스도 실제로는 91%가 탈 수 있었다. 조심하는 쪽으로 틀린다.
- 버스마다 구별하지 못해 '어려울 수 있음'은 사실상 나오지 않는다. 혼잡 칸은 확률 자체가 낮게 나온다(녹십자 평일 8:30~9:00: 앞 0명 93%, 3명 84%, 10명 64%).

- 재현: `.state` 실험 스크립트를 옮기지 않고 결과만 남긴다. 시험 기간이 8일이라 '못 탐' 비율은 수십 건 단위다.

## 응답 형식

기존 결과에 `fallback` 필드만 더한다. 수집·제공 정보가 오래돼 보류된 결과(`arrival_stale: true`)에만 들어가며, 그 결과의 `level`·`p_board`·`r_now` 등은 지금처럼 보류(`확률 보류`·`null`)다. 정상 결과에는 `fallback`이 없다.

| 필드 | `last_known` | `typical` | 뜻 |
|---|---|---|---|
| `mode` | ✓ | ✓ | `"last_known"` 또는 `"typical"` |
| `p_board` | ✓ | ✓ | 탈 확률(0~1) |
| `level` | ✓ | ✓ | `여유 있음`·`빠듯함`·`어려울 수 있음` |
| `age_sec` | ✓ | | 마지막 정보가 몇 초 전 것인지 |
| `r_now` | ✓ | | 마지막 정보의 차내 인원 |
| `load_pred` | ✓ | | 마지막 정보로 낸 도착 인원 예측 |
| `arrival_at` | ✓ | | 마지막 정보의 도착 예정 시각(ISO, +09:00) |
| `headway_min` | | ✓ | 이 칸의 보통 배차 간격(분, 없으면 `null`) |
| `full_share` | | ✓ | 이 칸에서 앞 0명이어도 못 탔던 비율 |
| `trips` · `basis` | | ✓ | 근거 운행 수와 칸 이름(점검용) |

예시(11-04 08:40 수집 중단을 재생한 값, 일부 반올림):

```json
{"level": "확률 보류", "p_board": null, "arrival_stale": true, "prediction_status": "collection_stale",
 "fallback": {"mode": "last_known", "age_sec": 346, "r_now": 16, "load_pred": 21.3,
              "arrival_at": "2026-11-04T08:45:10+09:00", "p_board": 0.813, "level": "빠듯함"}}
{"level": "확률 보류", "p_board": null, "arrival_stale": true, "prediction_status": "collection_stale",
 "fallback": {"mode": "typical", "p_board": 0.838, "level": "빠듯함", "headway_min": 9.4,
              "full_share": 0.068, "trips": 74, "basis": "sb02|32|wkd|17"}}
```

## 화면 문구안 (프론트 담당 결정)

- `last_known`
  - 배너: "실시간 정보가 잠시 끊겼어요 · {age_sec÷60}분 전 정보로 추정해요"
  - 남은 시간: `arrival_at` 기준 카운트다운에 "(추정)", 지나면 `typical` 문구로
  - 확률: 평소 카드 그대로 + "추정" 표시
- `typical`
  - 배너: "실시간 정보가 들어오지 않아 평소 이 시간 기준으로 안내해요"
  - 본문: "보통 약 {headway_min}분 간격 · 앞 {N}명이면 평소 {p_board}% 탈 수 있었어요"
  - 판정: `level` + "(평소 기준)"
  - `full_share ≥ 0.05`이면 "이 시간엔 가끔 만차예요"
- `fallback`이 `null`이면 지금 화면 그대로

## 프론트에서 바꿀 곳

- `arrivalState()`가 `updated_at`이 180초를 넘으면 `stale`로 보고 결과 카드를 "버스 정보 갱신 중"으로 덮는다. `fallback`이 있으면 그 자리에 대체 안내 카드를 보여준다.
- 응답 계약 검사(`contract.ts`)는 모르는 필드를 막지 않으므로 지금 화면은 `fallback`을 무시하고 그대로 동작한다.
